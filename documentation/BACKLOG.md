### BL-01c — Fact-extraction outbox has no mid-uptime recovery for hung (not crashed) tasks (source: BL-01b scoping decision, 2026-09-19)
**What:** BL-01b's recovery sweep (`_fact_extraction_recovery_sweep()` in `backend/app/main.py`) runs once at startup only. It correctly recovers a row left `pending` by a process crash/restart, but if the in-process extraction task silently hangs (e.g. network stall) without the process crashing, that row stays `pending` indefinitely until the next restart.
**Why deferred:** Deliberately scoped to the crash-recovery failure mode BL-01b's audit finding actually described; a periodic mid-uptime sweep is broader scope (needs a hang-timeout policy, not just an existence check) and wasn't part of the original acceptance criterion.
**What's needed:** If hung (not crashed) extraction tasks turn out to matter in practice, add a periodic sweep (e.g. alongside `_guest_cleanup_loop`) that reclaims `pending` rows older than some timeout and retries them.
**Touches:** `backend/app/main.py`.

### BL-06 — NPC→player and NPC↔NPC relationship drift is not mechanically driven (source: social_sim mode + Common Room work, 2026-09-17)
**What:** The numeric relationship extractor (see `backend/app/engine/prompt_builder.py` relationship layer and `backend/app/api/prompt_engine.py` turn extraction) only accepts player→NPC updates today; only the main NPC has a narrative-tag-driven affection path. `relationships.edges` in story JSON seed the *initial* state for all directed pairs (including NPC-NPC edges, as used in `backend/app/stories/6_common_room/`), and player-driven changes to player-facing edges are supported, but nothing updates NPC-initiated or NPC-NPC edges during play.
**Why deferred:** A genuinely dynamic ensemble house sim (e.g. Mina and Dae-ho's friendship visibly drifting from something the player does) needs this, but it's a meaningful extension of the turn-extraction schema, not a small patch, and was out of scope for adding the `mode` layer itself.
**What's needed:** Extend the single-call turn extractor's schema/prompt to propose NPC↔NPC and NPC→player relationship deltas (not just player→NPC), and apply them the same way player-facing deltas are applied today.
**Touches:** `backend/app/engine/extractors/turn_extractor.py`, `backend/app/api/prompt_engine.py`, `backend/app/engine/character_graph.py`.

### BL-08 — No quest/schedule/resource engine (source: social_sim mode + Common Room work, 2026-09-17; pre-existing gap)

**Touches:** `backend/app/engine/gameplay.py`, story JSON schema, `documentation/model_output_docs/GAME_DESIGN_SYSTEMS.md`.

### Six Strangers audit Phase 1 — truthful scenes and durable state — FULLY COMPLETE (2026-09-19, source: [audit and proposal](SIX_STRANGERS_AUDIT_PROPOSAL_2026_09_19.md))
**Status:** all six items the audit's own "Phase 1" section calls for are done and live-verified: `SceneContext` context-selection policy, versioned dedup/idempotent turn commits (BL-02), and durable outbox + crash recovery for background extraction (BL-01b), on top of the original two live-bug fixes (future-resident leakage, solitude/focal-NPC override) and the atomic turn-commit ordering (BL-01's other half). Only BL-01c (mid-uptime recovery for a hung, non-crashed extraction task) remains open, and that's a deliberately narrower follow-on scoped after BL-01b shipped, not a gap in Phase 1's own acceptance criteria.
**Resolved by:** six commits on `beta`, in order: `6c90667` (initial Phase 1 fixes), `308f4bb` (roster closure), `0265297` (prompt-contract strengthening), `224856e` (actual root cause), `8e7991a` (SceneContext consolidation), `be199c5` (BL-02 turn-retry idempotency), `9c2878a` (BL-01b durable fact-extraction outbox). The first four were all required to close the two original live bugs — a worked example of why live verification (not just local tests) is part of done: the first three of those four each passed the full local suite and *looked* complete, but each still failed live re-verification on the deployed beta site, because the underlying bug had more than one contributing cause.
**What was found:** live beta contradicted the roster and world state in two ways: asking about an upcoming resident (Arman) confirmed his residency and exposed his authored private concern; an explicit solitary-scene request ("I go to the rooftop alone") still had the focal NPC (Mizuki) narrated as joining.
**What was done, round by round (each verified live against `https://beta-api.storieschat.ai`, `six_strangers`, guest sessions, before moving to the next round):**
1. **`6c90667`** — filtered lifecycle-ineligible characters out of the turn extractor's candidate catalog (`character_key_to_name` in `prompt_engine.py`) and out of canonical-fact rendering (`_fact_owner_only_upcoming()` in `prompt_builder.py`); gated `_character_identity_section`/`_storyteller_scene_section`'s main-character framing on scene presence via new `_main_character_scene_eligible()`; fixed the BL-01 save-ordering gap (`over`/`last_turn_*` now set before the session save) and added `beliefs`/`observation_log` to `_serialize_state`/restore; added `backend/app/config/build_info.py` for real commit/environment identity on `/api/version`, `/version.json`, `/beta/version.json`, `/api/health`. **Live result:** solitude check passed; Arman check still failed 3/3 — the model reliably said "he's one of the housemates... moving in soon" even with his private fact removed, because nothing told the narrator that an unrecognized name should read as genuinely unfamiliar rather than as a known-but-absent housemate.
2. **`308f4bb`** — added an explicit roster-closure instruction to the scene brief: lists the complete active cast by name and instructs that any name not on it is unfamiliar to every character. **Live result:** Arman check now passed 3/3 with correct genuine-unfamiliarity responses; but a *re-check* of solitude (done as part of the same verification pass) found Mizuki now walking onto the rooftop and speaking in 3/4 trials — the scene-brief-only gating from round 1 was insufficient once verified at higher sample size.
3. **`0265297`** — traced the solitude regression to `system_prompt()`'s always-injected STORYTELLER CONTRACT ("Keep {char_name} as the focal character...") and FOCAL STATE ("The focal character is {char_name}") sections, which unconditionally asserted main-character focus regardless of scene presence, directly contradicting the scene brief. Also corrected a pre-existing test (`test_movement_preserves_combined_dialogue_and_destination_cast`) that had locked in the bug as expected behavior (asserted Mizuki's identity block MUST render in an empty room). **Live result:** solitude 8/8 clean (zero NPC mentions of any kind), Arman 4/4 correct — both fixes now hold at final verification.
5. **`8e7991a`** (2026-09-19, continuation) — consolidated the seven scattered scene-membership/knowledge-visibility functions (`_cast_scene_eligible`, `_get_active_character_keys`, `_get_people_present_keys`, `_get_scene_speaker_keys`, `_fact_owner_only_upcoming`, `_main_character_scene_eligible`, `_scene_presence_has_been_computed`) into a single `SceneContext` class (`backend/app/engine/scene_context.py`), per the audit's explicit recommendation for "one reusable context-selection policy" instead of point-patches. ### BL-03 — Beta/prod isolation via `/beta/` path (source: audit A15, P1 investigation) — CONFIRMED then fixed
**Resolved by:** live-verified via curl (`https://storieschat.ai/api/stories` lacked `common_room`; `https://beta-api.storieschat.ai/api/stories` had it, confirming the beta page was actually reaching prod), then fixed in `frontend/index.html`.
**What was done:** this was upgraded from "unverified" to a confirmed live bug: `frontend/index.html` computed `API_BASE = window.location.origin + "/api"`, so a page loaded from `https://storieschat.ai/beta/` called `https://storieschat.ai/api/...`, which Cloudflare routes to the **prod** Railway origin, not beta — meaning the hosted beta UI's chat feature was silently talking to prod. `frontend/debug.html` already had the correct fix for this exact problem (`_isBeta` detection → `beta-api.storieschat.ai`); `index.html` did not, despite already having a partial version of it for OAuth only (`LOGIN_AUTH_BASE`). Added `tests/frontend/test_beta_api_base.py` (no JS test harness exists in this repo, so this is a structural/string-level regression guard on the shipped file, not a real browser test). Full suite: 471 passed, 1 xpassed, 0 failed, 0 skipped.
